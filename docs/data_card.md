# Synthetic data card (Annex E)

| Field | What we did |
|---|---|
| **Purpose** | Citizen profiles, applications and appointments in the Annex C schema, plus a knowledge base for the fictional state of Mitrapur Pradesh. The data must exercise every rule boundary, amendments by date, OR-group eligibility, consent, multilingual answers, referrals and safe actions. |
| **Generator** | The AI coding assistant used to build the project (Claude) generated the knowledge base and the 25 base citizen profiles, with default temperature: 1 call for the citizen batch, about 6 calls for the knowledge base. `scripts/generate_citizens.py --llm ollama` regenerates citizens with the local model (qwen2.5:7b-instruct, temperature 0.7, batches of 5). The 13 edge-case citizens are written by code, not by an LLM. |
| **Prompts** | Verbatim: `backend/data/prompts/citizen_generation_prompt_v1.md` and `backend/data/prompts/kb_generation_prompt_v2.md` (an improved version of the Annex F starter prompt: amendments, outdated grievances, mixed-language notices, policy values). Raw model output for citizens: `backend/data/synthetic/llm_raw/`. |
| **Schema enforcement** | Pydantic model `LLMCitizen` in the generator: enum fields, ranges, date of birth → age 0–110 on 2026-11-21, disability consistency. Invalid profiles are rejected and logged in `generation_log.json`. IDs, fake phones (`000-000-NNNN`) and last-4 ID digits are assigned by code. The knowledge base was checked by a script that confirms every rule's `source_id`/`source_section` exists as a `## N` heading, every register file exists, and every title and ID matches. |
| **Row counts and distributions** | 38 citizens. Districts: Nayagaon 13, Kaverinadu 9, Sundarpur 8, Thenpuram 8. Residence: rural 24, urban 14. Preferred language: hi 18, kn 8, ta 8, en 4. Consent N: 5 (C1033–C1037). Income: ₹55,000–₹4,20,000, median ₹1,20,000; one profile has no income (edge case). Age on 2026-11-21: 16–76. 7 applications (4 submitted, one of them pending beyond 45 days; 2 approved; 1 rejected) and 2 appointments. |
| **Language coverage** | Knowledge base: 49 documents (en 23, hi 9, kn 7, ta 7, mixed 3) and 26 grievances (hi 6, en 6, kn 5, ta 5, mixed 4). Scheme names and document names are in all four scripts; reply templates are in en/hi/kn/ta/Hinglish. All non-English text was produced by the AI assistant. **A native-speaker check is still to be done and recorded below.** Eval messages: 50 cases (hi 4, hinglish 3, kn 4, ta 6 incl. Tanglish, en rest). |
| **Edge cases included** | C1001 income exactly ₹1,50,000 (pension limit) · C1002 ₹1,50,001 · C1003 turns 60 on 2026-11-21 · C1004 one day short of 60 · C1005 land exactly 5 acres (Kisan cap) · C1006 overlapping schemes (pension + Kisan + housing) · C1007 already applied · C1008 rejected application · C1009 application pending since 2026-08-14 · C1010 missing income/occupation/land · C1011 Medhavi last date is today · C1012 Suraksha last date was yesterday · C1013 income exactly at the Kanya Vidya limit. In the knowledge base: an extended last date (CIR-2026-011), a closure (CIR-2026-009), future-dated changes (CIR-2026-013, -014), an amendment not reflected in the rule rows (CIR-2026-016), 5 outdated grievance answers, and a forwarded message with an injected instruction (COM-2026-001). |
| **Validation results** | `python scripts/validate_data.py` → `backend/data/synthetic/validation_report.md`: 38 citizens, 7 applications, 2 appointments, **0 violations**. Checks: required columns, ID format and reserved range, duplicates, age and income not negative, disability 0–100 and consistent, only fake phones, only last-4 ID digits, no 12-digit IDs anywhere, statuses valid, dates not in the future, rejections have a reason, appointments created before their slot. The generator rejected 0 of 25 LLM profiles. |
| **What the LLM got wrong** | Found while building and testing: (1) circular CIR-2026-020 mentioned "no extension" while extending the date, which broke our first parser, so the parser now prefers an explicit "extended from X to Y"; (2) knowledge-base headings in Hindi-only documents had no English part, so the citation matcher uses section numbers; (3) boundary ages and incomes can't be trusted to an LLM, so the edge cases are generated by code. *Add native-speaker findings here.* |
| **Known limitations** | Names and incomes are plausible but not statistically representative. Every household has one income figure (no per-person income). There is no marital status, so no widow-pension scheme. Translations are unreviewed. Grievances are short. Service-centre capacity is not modelled. |
