## Method

- **End-to-end set** (`eval/eval_set.jsonl`): labelled requests run through the real API in an isolated database. Each case lists the checks it must pass: answer type, reply language, required/forbidden text, per-scheme verdict, per-rule result, expected citation, referral decision/queue/reasons, action outcome, no-leak strings and question limits. A case passes only if every check passes.
- **Retrieval set** (`eval/retrieval_set.jsonl`): questions in en/hi/kn/ta whose answer sits in a document of a stated language. Hit@6 = the expected document is in the top 6. Reported per language pair (question language → document language).
- **Critic set** (`eval/critic_set.jsonl`): 20 drafts labelled good/bad by a team member (wrong number, missing caveat, wrong language, promise, outdated number, PII, injection echo). Agreement = critic's answer/revise decision matches the human label.
- **PII scan**: seeded secrets (OTP, account, ID, phone) searched in every response, audit record, referral bundle and stored message; answers also scanned with the PII detector.

## What the numbers say

- **Best retrieval configuration on this set: bge-m3 + scheme boost** (84% strict hit@6). The deployed default is `intfloat/multilingual-e5-small` with scheme boost; switch `EMBEDDING_MODEL` if a larger model wins and its CPU latency is acceptable.
- **Weak pairs for the default model: kn→en, ta→en.** Kannada/Tamil questions usually retrieve the Kannada/Tamil summary of a guideline rather than the English original. This is why eligibility, documents and dates never depend on retrieval: they come from the rule tables and SQLite tools, and retrieval only supplies the citation, which is pinned to the exact guideline section by code.
- **Critic**: scoping evidence per scheme and flagging superseded values is what catches a limit borrowed from another scheme or an old limit/date (compare the scoped and unscoped rows). Lowering the threshold to 0.5 lets more wrong numbers through; no critic misses every bad draft.
- **Language handling**: structured answers are composed natively in each language from tool output (no translation step), so numbers, dates and verdicts are identical across languages (see the cross-language check). Free-text answers use retrieved passages in the citizen's language when one exists.
- **Caveat**: these cases were written by the team and used during development, so they measure regressions more than generalisation. Judges' unseen requests are the real test.
